# v0.20.0 release and upgrade notes

[中文说明](v0.20.0.zh-CN.md)

## Changes since v0.19.5

v0.20.0 adds three settings that were requested in issues, serves every route
with `net/http` instead of Fiber, and is stricter about configuration and about
the requests of proxy clients. Several defaults and error cases change. Read
[Upgrade](#upgrade) before replacing a running deployment.

### New settings

- **Redirects from passthrough origins are followed.** An allowlisted origin
  that answers with a redirect to a CDN host, as `pkgs.k8s.io` does, is now
  fetched by apt-proxy itself, and the file is cached under the URL the client
  asked for. The CDN host does not have to be on the allowlist: a target
  outside it is followed when it resolves to public addresses only, uses port
  80 or 443, does not lead from `https` to `http`, and apt-proxy connects to it
  directly. Otherwise the redirect is passed to the client as before, and a
  warning gives the reason. `passthrough_follow_redirects`
  (`-passthrough-follow-redirects`, `APT_PROXY_PASSTHROUGH_FOLLOW_REDIRECTS`)
  is on by default.
  [#196](https://github.com/soulteary/apt-proxy/pull/196),
  [#187](https://github.com/soulteary/apt-proxy/issues/187). See
  [Caching Third-Party Archives](../repository-configuration.md#caching-third-party-archives-passthrough).
- **Mirror election can be turned off, and official addresses are the
  default.** `mirrors.election: false` (`-mirror-election=false`,
  `APT_PROXY_MIRROR_ELECTION=false`) makes every distribution without a pinned
  mirror use its official address: `http://archive.ubuntu.com/ubuntu/`,
  `http://ports.ubuntu.com/ubuntu-ports/`, `https://deb.debian.org/debian/` and
  `https://dl-cdn.alpinelinux.org/alpine/`. Nothing is probed and the Ubuntu
  geo mirror API is not queried. CentOS has no official address and uses the
  first mirror of its list. With election on, the official address is the
  first candidate, the mirror in use until the first election has finished,
  and the fallback when an election finds no usable mirror. A
  `distributions.yaml` entry can name one with `official_url`.
  [#197](https://github.com/soulteary/apt-proxy/pull/197),
  [#188](https://github.com/soulteary/apt-proxy/issues/188). See
  [Custom Mirror Selection](../repository-configuration.md#custom-mirror-selection).
- **`mode` takes a set of distributions.** The value is `all` or a set of
  distribution IDs, the built-in ones and those that `distributions.yaml`
  defines: `--mode=debian,proxmox-pbs-client`, `APT_PROXY_MODE` in the same
  form, or a YAML list. Only the named distributions are routed. The others
  answer `404`, and no mirror is elected for them. The IDs are checked once
  `distributions.yaml` has been loaded, at startup and on every reload.
  [#198](https://github.com/soulteary/apt-proxy/pull/198),
  [#182](https://github.com/soulteary/apt-proxy/issues/182). See the
  [mode reference](../configuration-reference.md#mode).

### Data path and caching

- **Responses are streamed.** All routes are served by `net/http`; Fiber and
  fasthttp are no longer dependencies. The Fiber adaptor held every response
  body in memory until the handler returned, on a cache hit as well as on a
  miss, so a client received its first byte only after the upstream transfer
  had finished. In one measurement with a 256 MiB object, the peak resident
  memory of the proxy went from 1.2–1.9 GiB to about 24 MiB, and the first
  byte of a miss arrived after 0.01 s instead of 3.9–6.1 s. A client that
  disconnects during a miss now cancels its upstream fetch. The change also
  fixes three failures of the cache worker: a truncated upstream body could
  reach the client as a complete response, an upstream status code outside
  100–999 caused a panic, and a panic in the worker ended the process.
  [#185](https://github.com/soulteary/apt-proxy/pull/185)
- **Immutable artifacts are cached for APT and outlast a mirror outage.** APT
  sends `Cache-Control: max-age=0` with every index request, so by-hash index
  downloads always went to the mirror (`X-Cache: SKIP`). The built-in Ubuntu,
  Ubuntu Ports and Debian rules now mark versioned pool artifacts and by-hash
  paths as `immutable`, and for these paths a zero `max-age` in the request no
  longer bypasses the cache. When the revalidation of an expired immutable
  entry fails with a transport error or a 5xx status, the stored copy is
  served. [#191](https://github.com/soulteary/apt-proxy/pull/191). See
  [Immutable artifacts and upstream failures](../repository-configuration.md#immutable-artifacts-and-upstream-failures).
- **Snapshots of the official archives.** `apt-proxy repository prefetch`
  failed against deb.debian.org and archive.ubuntu.com, which list
  uncompressed `Packages` and `Sources` indexes they do not publish. The
  offline server answered `400` to every path with a percent escape, which APT
  sends for `+` and `~` in package versions. A listed variant that the origin
  answers with `404` is now left out of the snapshot, and objects are looked up
  by the decoded path. [#190](https://github.com/soulteary/apt-proxy/pull/190).
  See [snapshot commands and limits](../repository-offline.md).

### Mirror election

- **Every candidate is probed.** An election used to end after the first three
  answers, which favored plain-http mirrors, and it followed redirects, so a
  candidate could be measured by a host other than the one the proxy fetches
  from. Every candidate is now probed without following redirects, at most
  eight at a time. A status other than `200` or a `text/html` answer fails the
  candidate. A mirror that answers on both schemes is elected as `https`.
- **Benchmark paths and lists.** The Ubuntu Ports and Debian benchmark paths
  are now `dists/devel/Release` and `dists/stable/Release`. The Ubuntu Ports
  path in `config/distributions.yaml` named a location below a file, which
  mirrors answer with `404`, so with that file loaded each Ubuntu Ports
  election failed. Hosts that answer `404` for `ubuntu-ports` were removed
  from its list.
- **A refresh keeps what it cannot replace.** When one distribution cannot
  elect a mirror, it keeps the mirror it is being served from, and the other
  distributions are refreshed. Before, the whole refresh failed with `503`.
  [#192](https://github.com/soulteary/apt-proxy/pull/192)

### Request routing and upstream access

- **Allowlisted origins and credentials of proxy clients.** For a client that
  uses apt-proxy as its HTTP proxy, an allowlisted origin whose paths start
  like a distribution's, such as `packages.microsoft.com/ubuntu/...`, was
  rewritten onto that distribution's mirror. It is now fetched from the
  origin. Credentials such a client sends for the host it names are no longer
  forwarded when routing selects a different host.
  [#189](https://github.com/soulteary/apt-proxy/pull/189). See
  [private repositories](../private-repositories.md).
- **Distribution requests are fetched only from their mirror.** A request that
  matches a distribution but cannot be pointed at a mirror is answered with
  `404`. [#194](https://github.com/soulteary/apt-proxy/pull/194)
- **`upstream_access` with HTTP/2 upstreams.** With the policy enabled, a
  request to an HTTPS upstream that negotiates HTTP/2 failed with `502`
  (`malformed HTTP response` or `EOF` in the log). Package downloads, mirror
  probes and Metalink fetches were affected, in every release since the policy
  was added in v0.18.0. [#195](https://github.com/soulteary/apt-proxy/pull/195)

### Configuration loading

- **`apt-proxy.yaml` is read strictly.** An unknown key, more than one YAML
  document, or a `${VAR}` reference to an unset variable used to be accepted
  without a message: the key was dropped, and the literal text `${VAR}` became
  the value, for example of the API key. Each is now a startup error.
- **Omitted keys keep their defaults.** `security.api_rate_limit_per_minute`
  and `storage.s3.use_ssl` default to 60 and `true`. A config file that
  omitted them used to set 0 and `false`.
- **Empty environment variables.** A variable that is set but empty no longer
  overrides a boolean, numeric or `mode` setting of the file, and an empty API
  key no longer turns authentication off.
  [#186](https://github.com/soulteary/apt-proxy/pull/186)

### Toolchain and dependencies

- Go 1.27.4, which fixes GO-2026-6859 in the `net/http` server.
  [#193](https://github.com/soulteary/apt-proxy/pull/193)
- `golang.org/x/sync` 0.25.0. `github.com/gofiber/fiber/v3` and
  `github.com/valyala/fasthttp` are removed.

## Upgrade

Pin the new image or replace the binary from the release archives:

```sh
docker pull soulteary/apt-proxy:v0.20.0
# Equivalent registry:
docker pull ghcr.io/soulteary/apt-proxy:v0.20.0
```

Keep your configuration and the persistent cache volume. The cache format is
unchanged. Go through the points below before switching clients over.

### Startup can fail where v0.19.5 started

- `apt-proxy.yaml` contains an unknown key, a second YAML document, or a
  `${VAR}` reference to an unset variable. The error names the line and field,
  or the variables. Correct the key, or write `${VAR:-default}` (`${VAR:-}`
  for an empty value) for an optional variable.
- `mode` is neither `all` nor a registered distribution ID. v0.19.5 treated
  such a value as `all`. The error lists the registered IDs.

### Defaults that change

- **Passthrough redirects.** With `passthrough` configured, apt-proxy can now
  connect to public hosts that are not on the allowlist, because an
  allowlisted origin redirected to them. The startup log says so. Set
  `passthrough_follow_redirects: false` to keep upstream fetches within the
  allowlist; every redirect then reaches the client, as in v0.19.5.
- **S3 over HTTPS.** A config file that selects the S3 backend without
  `use_ssl` now connects over HTTPS. A plain-HTTP endpoint, such as a local
  MinIO, needs `use_ssl: false`.
- **Management API rate limit.** A config file without
  `api_rate_limit_per_minute` limits the management API to 60 requests per
  minute and client IP. `0` disables the limit.
- **Empty environment variables.** `APT_PROXY_ENABLE_API_AUTH=`,
  `APT_PROXY_CACHE_MAX_SIZE=` and similar empty values no longer change a
  setting. Use an explicit `false` or `0`. String and list variables are
  unchanged: an empty `APT_PROXY_UBUNTU` still clears the mirror the file
  selects.

### Mirrors and the cache

- **The mirror in use can change, and with it the cache key.** Cache entries
  are keyed by the upstream URL. Until the first election has finished, the
  mirror is the official address instead of the first listed mirror. A mirror
  that answers on both schemes is elected as `https`, and built-in aliases
  such as `cn:tsinghua` resolve to `https://`. A deployment whose mirror URL
  changes starts with a cold cache for that distribution once. Pin the
  previous URL to keep it. A deployment that pins a built-in alias and allows
  only outbound port 80 has to name the `http://` URL.
- **Elections take longer.** Every candidate is probed three times, within the
  unchanged limit of 30 s. Startup does not wait for an election; `SIGHUP` and
  `POST /api/mirrors/refresh` do.
- **Stricter candidates.** A mirror in a custom `distributions.yaml` that
  answers the benchmark path with a redirect, a status other than `200` or an
  HTML page is no longer elected.
- **by-hash index files are stored.** They take cache space until TTL or size
  eviction.

### Proxy clients

- Credentials that a proxy client sends for the host it names no longer reach
  a mirror on a different host. Put the credentials in the mirror URL, or
  address apt-proxy directly.
- An allowlisted host that is not a host of a distribution is always fetched
  from that host, including for paths such as `/ubuntu/...`, under the
  origin's own `Cache-Control`.
- A path with dot segments answers `404`. A request for a distribution that
  `mode` does not serve answers `404` instead of `400`.

### Offline snapshots

- A snapshot created by v0.20.0 can hold a subset of the index variants that
  `Release` lists. v0.19.5 and earlier reject such a snapshot and its archive.

### Rollback

Restore the v0.19.5 image or binary with the same cache volume. v0.19.5 does
not know the settings introduced here, so remove them first. It stops on a
`mode` list in `apt-proxy.yaml` and on the flags `-mirror-election` and
`-passthrough-follow-redirects`. It ignores `mirrors.election` and
`passthrough_follow_redirects` in the file, and treats a comma-separated
`--mode` as `all`. It rejects a `distributions.yaml` that contains
`official_url` and then runs with the built-in distributions only, logging a
warning.

For an upgrade from v0.19.4 or earlier, also read the [v0.19.5 notes](v0.19.5.md)
and the earlier notes they link.

## Validation and artifacts

Each change was merged through a pull request with its CI and security scan
checks passing. The merged tree passed the real-client matrix of 18 client
images and its evidence gate, `go test -race`, and the coverage gate with
96.8% total statement coverage. The release workflow runs the client matrix
again before it publishes. These signed local fixtures verify package
installation and cache reuse; they do not certify every public mirror or
every client CPU architecture. See [verified client support](../client-support.md).

The artifacts are those of v0.19.5: Linux and macOS binary archives, Linux
`.deb`, `.rpm` and `.apk` packages, archive SBOMs and `checksums.txt`. Docker
Hub and GHCR publish `linux/amd64`, `linux/arm64` and `linux/arm/v7`
manifests.
