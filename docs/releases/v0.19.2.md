# v0.19.2

APT Proxy v0.19.2 fixes repository selection when a third-party archive shares
a path prefix with a built-in distribution, validates distribution YAML fields,
and adds a Proxmox Backup Client example.

[中文升级说明](v0.19.2.zh-CN.md)

## Changes

- **Route Proxmox requests to the configured Proxmox repository.** A distribution
  matching both the original request host and path now takes priority over
  generic path-only routes. With the corresponding host and path configured,
  requests to `download.proxmox.com/debian/pbs-client/...` no longer get claimed
  by the built-in Debian `/debian/` route. This addresses
  [#167](https://github.com/soulteary/apt-proxy/issues/167) through
  [#170](https://github.com/soulteary/apt-proxy/pull/170).
- **Report invalid distribution fields.** Unknown YAML keys, such as
  `cache-control` instead of `cache_control`, now produce errors with the field
  name and line number. Additional YAML documents are rejected.
- **Improve examples and diagnostics.** The
  [Proxmox Backup Client example](../../examples/proxmox/) covers the official
  HTTP source, a distinct local path alias, and direct-versus-proxied checks.
  Rewrite debug logs include the selected distribution ID. English and Chinese
  documentation clarify that neither `404` nor `cache: SKIP` alone proves that
  configuration loading failed.
- **Refresh dependencies and CI tools.**
  [#168](https://github.com/soulteary/apt-proxy/pull/168) updates `health-kit/v4`
  from v4.0.2 to v4.0.3.
  [#169](https://github.com/soulteary/apt-proxy/pull/169) updates the Go test-report,
  Go Report Card, Docker-login and SARIF-upload actions. The Go toolchain remains
  at 1.27.3, as in v0.19.1.

## Upgrade notes

**Distribution configuration validation is intentionally stricter.** Before
upgrading, review `distributions.yaml` for misspelled or unsupported keys:

- Use `cache_control` for cache directives.
- Keep the file to a single YAML document.
- Keep anchors and merges within recognized fields. Arbitrary top-level
  anchor-helper keys must be moved into the supported schema.

Empty files remain valid. These rules apply to distribution configuration, not
to the main server configuration.

Startup and reload error handling is unchanged: an invalid startup distribution
file produces a warning and leaves built-in distributions available; a failed
reload preserves the active routing configuration. Check startup or reload logs
to confirm that custom configuration loaded successfully.

`host_pattern` remains a routing preference and fallback, not a host access
control rule. Local path aliases continue to work. Equally eligible
distributions retain the existing deterministic order. A selected distribution
without a matching cache rule still returns `404` instead of falling through
to another repository.

## Validation before release

The routing failure was reproduced against two independent local upstreams
before the fix. All 33 added routing scenarios pass after the fix and verify
the actual upstream, Host, path and query. Distribution-loader tests cover
unknown fields, empty files, additional YAML documents, supported anchors and
merges, and preservation of the active configuration after a failed reload.

The full local race-enabled test suite and `go vet` passed. Total statement
coverage was 83.6%, above the project's 80% threshold. PR #170 also passed
[CI](https://github.com/soulteary/apt-proxy/actions/runs/40508913109)
and the [security scan](https://github.com/soulteary/apt-proxy/actions/runs/40508913111).
These are the local and PR validation results; the version-tag workflows run
the release gates separately. The routing regressions use controlled local
origins and do not claim live verification of the public Proxmox repository.
