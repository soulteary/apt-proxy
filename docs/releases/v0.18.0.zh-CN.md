## 六项新增能力

- **完整仓库快照与离线维护。** `apt-proxy repository prefetch` 获取所选 suite、
  component、二进制架构及可选 Sources 索引引用的全部对象，校验大小和 SHA256 后原子发布。
  `verify`、`repair`、`export`、`import`、`serve` 操作这份完整的选定集合。
  离线服务没有网络回退，原始仓库签名和有效期仍由 APT 验证。
  详见[快照命令与限制](../repository-offline.md)。
- **基于快照指纹的运行时镜像切换。** 可选的 `mirror_health` 映射为运维者明确认可的
  等价公共 Debian 系仓库提供有界故障切换。替代镜像必须与全部已完整观察且仍有效的
  Release/InRelease 指纹完全一致；未知、过期、不同或私有快照不会切换。
  探测有时间与大小限制，状态通过受现有管理策略保护的 `GET /api/mirrors/status` 提供。
  它检查元数据一致性，不负责 OpenPGP 验证，也不提供原子仓库快照。
  详见[运行时镜像健康](../runtime-mirror-health.md)。
- **持久缓存完整性。** 守护进程默认启用 `cache.integrity: sha256`，私有记录绑定
  响应体摘要与长度、请求键、状态、响应头和代际。损坏记录按未命中处理，不删除并发发布的
  新替代版本；校验支持 S3 并在重启后继续生效。详见[完整性与 I/O 成本](../cache-integrity.md)。
- **真实 APT 客户端测试。** Debian Bookworm/Trixie、Ubuntu 22.04/24.04 运行签名更新、
  安装、源码下载、SHA256 by-hash、明确断言的 gzip 回退、范围请求、重试、中断恢复、
  认证 HTTPS 与导入后的离线访问。运行器支持 digest 固定和较长镜像引用，在清理前拒绝
  冲突的证据标识，CI 失败时也上传证据。测试不表示所有公共镜像均兼容。
  详见[客户端矩阵](../apt-client-tests.md)。
- **共享暂存与下载准入。** 每个进程统一约束未知长度落盘、HTTP 缓存响应副本、
  原生磁盘发布暂存及 S3 内存/落盘副本。已声明长度的下载也受对象大小与活跃下载上限约束，
  磁盘准入保留可用空间。详见[资源限制](../resource-limits.md)。
- **显式仓库身份与 Unix 共享磁盘协调。** 明确映射的公共 SHA256 by-hash 索引只有在
  响应体与 URL 中的摘要一致后才能共享身份。内核文件锁协调跨进程发布与 miss 等待者，
  持久失效屏障保护新代际。启用协调时，普通软件包与可变元数据按进程隔离；私有请求
  不加入共享缓存。详见[配置与维护边界](../shared-repository-cache.md)。

## 正确性与依赖更新

- 在 Fiber/fasthttp 复用请求缓冲区前独立持有元数据，异步发布期间保留 URL、
  header、Vary 选择字段以及调用方 context 的值和截止时间。
- 在应用预关闭时取消上游工作，再排空连接和关闭缓存。相同调用方生命周期复用
  取消域，避免每个已结束请求留下一个取消回调。
- 协调缓存填充的内部重查不再重复增加原生 hit/miss 统计，同时保留完整性和失效检查。
- 缓存包装层保留替代发布顺序、跨实例 header 代际、完整 Vary 与客户端条件请求语义。
- 已发布缓存库的版本化 Vary GET 键在关闭摘要校验时，普通读取与协调重查仍执行长度校验，
  HEAD 保留元数据语义。窄范围桥接适配 Fiber v3.6.0，保留已识别的 apt-cacher-ng
  `HTTPS///` 重写标记，普通路由的斜杠/转义检查、下载访问控制、稳定取消 context
  和流式 trailer 也继续生效。
- CLI 或环境变量显式提供的 `0` 缓存容量、TTL 和清理间隔现在正确关闭对应控制。
  省略时保留普通默认值 10 GiB、7 天和 1 小时，YAML 非正缓存字段仍保留默认值。
  关闭后端 TTL 不改变 HTTP 新鲜度和源站指令。
- 用已发布的 [httpcache-kit v4.1.0](https://github.com/soulteary/httpcache-kit/releases/tag/v4.1.0)
  与 [vfs-kit v1.4.5](https://github.com/soulteary/vfs-kit/releases/tag/v1.4.5)
  替换临时提交版本。
- Fiber 从 v3.5.0 升级到 v3.6.0，MinIO Go 客户端从 v7.3.0 升级到 v7.4.1。
- 间接依赖 klauspost/compress 从 v1.20.1 升级到 v1.20.3。
  Go 工具链仍为 v1.27.2，发布工作流固定使用 GoReleaser v2.18.3。
  其余解析后的依赖以 `go.mod` 与 `go.sum` 为准。

## 从 v0.17.2 升级

1. 保留当前二进制/镜像引用和配置。停进程后再做一致的磁盘缓存备份；
   离线快照使用独立目录，避免与守护进程的可清理缓存混放。
2. 为一次缓存重新预热预留源站流量。缺少私有 SHA256 元数据的旧条目按未命中惰性下载；
   私有隔离命名空间让更早可能包含认证内容的条目不可达，但不删除旧文件。
   httpcache-kit v4.1.0 另外版本化了 Vary 命名空间，旧持久 variant 安全未命中并重新预热；
   普通 non-Vary 基础键不受这项库迁移影响。无需手动 purge，普通单实例清理可回收旧对象。
3. 评估完整性校验成本。命中前读取完整响应体，包括 HEAD；S3 可能需传输整个对象后
   才返回首字节。普通模式可显式设置 `cache.integrity: none` 接受性能权衡，
   但启用 `shared_cache` 时仍强制 SHA256 校验。摘要检测意外损坏，不能阻止能改写
   缓存记录的攻击者重算摘要；APT 的签名和软件包验证仍不可替代。
4. 检查下面的默认额度。大于 1 GiB 的 CUDA、内核或工具链对象需要显式提高磁盘对象上限。
   S3 单次 PUT 最大为 5120 MiB。零值选择默认值，不表示无限制。
   旧式 `download` 落盘限制仍是额外约束；省略 `resources.total_temp_mb` 时，
   显式的 `download.total_spool_mb` 会提供共享总额度。
5. 使用 S3 也需可写本地暂存空间。内联数据与切换到落盘时重叠的副本都计入共享预算；
   这是 payload 副本预算，不是 RSS 或文件系统全局配额。HTTP 缓冲、元数据、持久条目
   及其他进程仍需额外余量。资源计数按进程计算，共享卷也不例外。
6. 明确启用可选能力。省略 `mirror_health` 和 `shared_cache` 时，不启用运行时切换
   或共享身份。`repository` 是使用独立额度和目录的显式命令。主 YAML 新能力配置变更
   需重启；SIGHUP/API 刷新重新加载发行版路由，成功选优后重置镜像健康状态。
7. 使用 Unix 共享磁盘时，停止并一起升级所有共享实例，保持相同仓库策略。缓存/锁目录
   必须私有，所在文件系统须支持进程共享 `flock`；运行期间不能删除锁文件。
   TTL/MaxSize 淘汰、后台清理与启动暂存扫描被关闭，全局在线 purge 被拒绝；维护缓存
   或孤立暂存文件前须停止所有实例。S3/Windows 共享协调不可用，S3 实例应使用独立前缀。

```yaml
cache:
  integrity: sha256
resources:
  max_object_mb: 1024       # MiB，即 1 GiB
  total_temp_mb: 4096       # MiB，每个进程 4 GiB
  max_active_downloads: 32
  min_free_mb: 128
download:
  max_spool_mb: 1024        # 未知长度落盘的额外限制
  total_spool_mb: 4096
  timeout_seconds: 1200    # 20 分钟
```

活跃下载或共享暂存预算拒绝时返回 `503` 与 `Retry-After: 1`；旧式未知长度落盘子限制
仍返回 `502`。上游完整响应已送达后，缓存副本超额只跳过发布，不丢弃该响应。
缓存命中不占上游槽位。预算控制的可缓存 GET 可以用 HTTP trailer 报告 `X-Cache-Staging`；
`ADMITTED` 表示暂存准入，不代表异步提交已经完成。

## 快照与私有仓库边界

快照包含所选索引中的全部包/源码对象，不计算某一个软件包的依赖闭包。其他 suite、
component 或架构需要另行选择。可选翻译、Contents、AppStream 和安装器树不属于这份
快照集合。历史代际累积占用可能超过单次操作的总字节上限。

选中的 xz 索引需要 `PATH` 中有 `xz`。普通 distroless 镜像不含它，
可构建 `docker/Dockerfile.offline` 使用包含 xz 和 CA 证书的离线镜像。
预取、导入与修复要求服务账户拥有可写目录；已有完整快照可以只读挂载运行服务。
快照命令暂不支持认证私有源站。

在线认证请求仍只向配置的上游传递凭据，并使用 no-store 绕过缓存。可选镜像切换不参与
这些请求，共享缓存还排除未知自定义 header 和请求体。明确配置受信任的源站与私网访问例外，
详见[私有仓库隔离](../private-repositories.md)。

## 发布前验证

v0.18.0 最终候选的发布验证使用以下 Go 检查与当时的四项 APT 客户端矩阵：

```sh
go mod verify
go test -race -cover ./...
go vet ./...
bash tests/apt-client/matrix.sh
```

检查每个客户端的证据与对应提交的 CI。现有徽章快照不能证明新的依赖图已通过验证。
发布构建使用 `go.mod` 声明的工具链，正式产物、签名客户端测试和校验和须来自确认的版本。

## 回退

保留上一版程序和配置。回退前停止所有共享实例，恢复匹配配置，并使用独立旧缓存目录/前缀
或停机备份，不让新旧实例同时写共享存储。旧版本不理解新的完整性/协调策略，不能假定
新的私有记录或 Vary 键在旧程序中仍可用。离线快照目录应始终独立于守护进程缓存维护。
