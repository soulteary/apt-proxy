# v0.20.0 发布与升级说明

[English](v0.20.0.md)

## 相比 v0.19.5 的变化

v0.20.0 新增三项来自 issue 的配置能力，所有路由改由 `net/http` 提供（不再使用
Fiber），并对配置文件和代理客户端的请求做了更严格的处理。若干默认值和报错情形
随之变化，替换线上部署前请先阅读[升级](#升级)。

### 新增配置

- **由代理跟随白名单源站的重定向。** 白名单里的源站如果把请求重定向到 CDN 主机
  （`pkgs.k8s.io` 就是这样），现在由 apt-proxy 自己去取，文件缓存在客户端请求的
  URL 之下。CDN 主机不需要写进白名单：名单外的目标只要解析出的地址全部是公网
  地址、端口是 80 或 443、不是从 `https` 降到 `http`，并且 apt-proxy 是直连
  出去的，就会被跟随。否则重定向仍像以前一样交给客户端，日志里有一条警告说明
  原因。`passthrough_follow_redirects`（`-passthrough-follow-redirects`、
  `APT_PROXY_PASSTHROUGH_FOLLOW_REDIRECTS`）默认开启。
  [#196](https://github.com/soulteary/apt-proxy/pull/196)、
  [#187](https://github.com/soulteary/apt-proxy/issues/187)。详见
  [缓存第三方软件源](../repository-configuration.zh-CN.md#缓存第三方软件源passthrough)。
- **可以关闭镜像选优，官方地址成为默认。** `mirrors.election: false`
  （`-mirror-election=false`、`APT_PROXY_MIRROR_ELECTION=false`）让每个没有固定
  镜像的发行版直接使用官方地址：`http://archive.ubuntu.com/ubuntu/`、
  `http://ports.ubuntu.com/ubuntu-ports/`、`https://deb.debian.org/debian/` 和
  `https://dl-cdn.alpinelinux.org/alpine/`。此时不探测任何镜像，也不查询 Ubuntu
  的地理镜像 API。CentOS 没有官方地址，使用其列表中的第一个镜像。开启选优时，
  官方地址是第一个候选、首次选优完成前使用的镜像，以及选优找不到可用镜像时的
  兜底。`distributions.yaml` 的条目可以用 `official_url` 指定官方地址。
  [#197](https://github.com/soulteary/apt-proxy/pull/197)、
  [#188](https://github.com/soulteary/apt-proxy/issues/188)。详见
  [自定义镜像选择](../repository-configuration.zh-CN.md#自定义镜像选择)。
- **`mode` 接受发行版集合。** 取值为 `all`，或一组发行版 ID：内置的，以及
  `distributions.yaml` 里定义的。写法是 `--mode=debian,proxmox-pbs-client`、
  同样格式的 `APT_PROXY_MODE`，或 YAML 列表。只有列出的发行版参与路由，其余
  返回 `404`，也不会为它们选优。ID 在 `distributions.yaml` 加载之后校验，启动
  时和每次重载时都会校验。
  [#198](https://github.com/soulteary/apt-proxy/pull/198)、
  [#182](https://github.com/soulteary/apt-proxy/issues/182)。详见
  [模式说明](../configuration-reference.zh-CN.md#模式mode)。

### 数据通路与缓存

- **响应改为流式传输。** 所有路由由 `net/http` 提供，Fiber 和 fasthttp 不再是
  依赖。此前 Fiber 的适配层会把每个响应体完整留在内存里，直到处理函数返回，
  命中和未命中都是如此，客户端要等上游传输全部结束才收到第一个字节。在一次
  256 MiB 对象的测量中，代理的常驻内存峰值从 1.2–1.9 GiB 降到约 24 MiB，
  未命中时首字节到达时间从 3.9–6.1 秒降到 0.01 秒。未命中期间客户端断开，
  现在会取消对应的上游请求。这次改动还修复了缓存工作协程的三个故障：被截断的
  上游响应体可能被当作完整响应交给客户端；上游返回 100–999 之外的状态码会
  引发 panic；工作协程里的 panic 会让整个进程退出。
  [#185](https://github.com/soulteary/apt-proxy/pull/185)
- **不可变制品可被 APT 命中缓存，镜像故障时仍可提供。** APT 的每个索引请求都带
  `Cache-Control: max-age=0`，因此 by-hash 索引每次都回源（`X-Cache: SKIP`）。
  内置的 Ubuntu、Ubuntu Ports 和 Debian 规则现在把带版本号的 pool 制品和
  by-hash 路径标记为 `immutable`，对这些路径，请求里的 `max-age=0` 不再绕过
  缓存。过期的不可变条目在重新校验时如果遇到传输错误或 5xx，会提供已存储的
  副本。[#191](https://github.com/soulteary/apt-proxy/pull/191)。详见
  [不可变文件与上游故障](../repository-configuration.zh-CN.md#不可变文件与上游故障)。
- **可以对官方仓库做完整快照。** `apt-proxy repository prefetch` 此前无法对
  deb.debian.org 和 archive.ubuntu.com 完成：它们在 Release 里列出了未压缩的
  `Packages` 和 `Sources` 索引，但并不发布这些文件。离线服务对所有带百分号
  转义的路径返回 `400`，而 APT 会对软件包版本里的 `+` 和 `~` 做转义。现在，
  源站返回 `404` 的已列出变体不进入快照，对象按解码后的路径查找。
  [#190](https://github.com/soulteary/apt-proxy/pull/190)。详见
  [快照命令与限制](../repository-offline.md)。

### 镜像选优

- **探测全部候选。** 此前选优在收到前三个应答后就结束，这有利于明文 http
  镜像；探测还会跟随重定向，候选镜像的成绩可能来自另一台主机，而不是代理实际
  取文件的那台。现在每个候选都会被探测，不跟随重定向，最多八个并发。状态码
  不是 `200` 或返回 `text/html` 的候选判为失败。同时支持两种协议的镜像以
  `https` 当选。
- **测速路径与镜像列表。** Ubuntu Ports 和 Debian 的测速路径改为
  `dists/devel/Release` 和 `dists/stable/Release`。`config/distributions.yaml`
  里原先的 Ubuntu Ports 路径指向一个文件之下的位置，镜像对它返回 `404`，
  因此加载该文件时 Ubuntu Ports 的每次选优都会失败。对 `ubuntu-ports` 返回
  `404` 的主机已从其列表中移除。
- **刷新时保留无法替换的部分。** 某个发行版选优失败时，它沿用正在使用的镜像，
  其余发行版照常刷新。此前整个刷新会以 `503` 失败。
  [#192](https://github.com/soulteary/apt-proxy/pull/192)

### 请求路由与上游访问

- **代理客户端的白名单源站与凭据。** 对于把 apt-proxy 当作 HTTP 代理的客户端，
  白名单里路径以发行版前缀开头的源站（例如 `packages.microsoft.com/ubuntu/...`）
  此前会被改写到该发行版的镜像，现在从源站本身获取。这类客户端为它点名的主机
  发送的凭据，在路由选中另一台主机时不再转发。
  [#189](https://github.com/soulteary/apt-proxy/pull/189)。详见
  [private repositories](../private-repositories.md)。
- **发行版请求只从它的镜像获取。** 匹配到发行版、但无法指向镜像的请求返回
  `404`。[#194](https://github.com/soulteary/apt-proxy/pull/194)
- **`upstream_access` 与 HTTP/2 上游。** 启用该策略后，对协商出 HTTP/2 的 HTTPS
  上游的请求会以 `502` 失败（日志里是 `malformed HTTP response` 或 `EOF`）。
  软件包下载、镜像探测和 Metalink 获取都受影响，自 v0.18.0 引入该策略起的每个
  版本都存在这个问题。[#195](https://github.com/soulteary/apt-proxy/pull/195)

### 配置加载

- **严格读取 `apt-proxy.yaml`。** 未知字段、多个 YAML 文档、引用了未设置变量的
  `${VAR}`，此前都会被悄悄接受：字段被丢弃，`${VAR}` 这段字面文本则成为取值，
  例如成为 API 密钥。现在这三种情况都会让启动失败。
- **省略的字段保持默认值。** `security.api_rate_limit_per_minute` 和
  `storage.s3.use_ssl` 的默认值是 60 和 `true`。此前配置文件省略它们时，实际
  取值是 0 和 `false`。
- **空的环境变量。** 设置了但为空的变量不再覆盖文件里的布尔、数值或 `mode`
  配置，空的 API 密钥也不再关闭认证。
  [#186](https://github.com/soulteary/apt-proxy/pull/186)

### 工具链与依赖

- Go 1.27.4，修复 `net/http` 服务端的 GO-2026-6859。
  [#193](https://github.com/soulteary/apt-proxy/pull/193)
- `golang.org/x/sync` 升到 0.25.0。移除 `github.com/gofiber/fiber/v3` 和
  `github.com/valyala/fasthttp`。

## 升级

更新镜像标签，或使用 Release 中的二进制替换：

```sh
docker pull soulteary/apt-proxy:v0.20.0
# 也可使用：
docker pull ghcr.io/soulteary/apt-proxy:v0.20.0
```

保留现有配置与持久化缓存卷，缓存格式没有变化。切换客户端之前，请逐项核对下面
的内容。

### v0.19.5 能启动、新版本可能启动失败的情况

- `apt-proxy.yaml` 里有未知字段、第二个 YAML 文档，或引用了未设置变量的
  `${VAR}`。报错会给出行号和字段名，或变量名。请改正字段；可选变量请写成
  `${VAR:-default}`（空值写 `${VAR:-}`）。
- `mode` 既不是 `all`，也不是已注册的发行版 ID。v0.19.5 会把这样的值当作
  `all`。报错会列出已注册的 ID。

### 发生变化的默认行为

- **白名单源站的重定向。** 配置了 `passthrough` 之后，apt-proxy 现在可能连接
  白名单之外的公网主机，因为白名单里的源站把它重定向到了那里。启动日志会说明
  这一点。设置 `passthrough_follow_redirects: false` 可以把上游抓取限制在白名单
  之内，此时所有重定向都交给客户端，与 v0.19.5 相同。
- **S3 默认走 HTTPS。** 配置文件选择 S3 后端但没写 `use_ssl` 时，现在通过
  HTTPS 连接。明文 HTTP 的端点（例如本地 MinIO）需要写 `use_ssl: false`。
- **管理 API 限流。** 配置文件没写 `api_rate_limit_per_minute` 时，管理 API
  按每个客户端 IP 每分钟 60 次限流。`0` 表示不限流。
- **空的环境变量。** `APT_PROXY_ENABLE_API_AUTH=`、`APT_PROXY_CACHE_MAX_SIZE=`
  这类空值不再改变配置，请显式写 `false` 或 `0`。字符串和列表类变量不变：空的
  `APT_PROXY_UBUNTU` 仍会清除文件里选定的镜像。

### 镜像与缓存

- **使用的镜像可能改变，缓存键随之改变。** 缓存条目以上游 URL 为键。首次选优
  完成之前，使用的镜像是官方地址，而不是列表中的第一个镜像。同时支持两种协议
  的镜像以 `https` 当选，`cn:tsinghua` 这类内置别名解析为 `https://`。镜像 URL
  发生变化的部署，该发行版的缓存会冷启动一次。想保留原来的 URL，请显式固定
  它。固定了内置别名、又只放行出站 80 端口的部署，需要改写成 `http://` 的
  完整 URL。
- **选优耗时更长。** 每个候选探测三次，总时限仍是 30 秒。启动不等待选优；
  `SIGHUP` 和 `POST /api/mirrors/refresh` 会等待。
- **候选要求更严。** 自定义 `distributions.yaml` 里的镜像，如果对测速路径返回
  重定向、非 `200` 状态码或 HTML 页面，不会再当选。
- **by-hash 索引文件会被存储。** 它们占用缓存空间，直到 TTL 到期或按容量淘汰。

### 代理客户端

- 代理客户端为它点名的主机发送的凭据，不再到达位于另一台主机的镜像。请把凭据
  写进镜像 URL，或直接访问 apt-proxy。
- 白名单里不属于任何发行版的主机，始终从该主机获取，包括 `/ubuntu/...` 这样的
  路径，并沿用源站自己的 `Cache-Control`。
- 带点号路径段的请求返回 `404`。请求 `mode` 未启用的发行版返回 `404`，而不是
  `400`。

### 离线快照

- v0.20.0 创建的快照可以只包含 `Release` 所列索引变体的一部分。v0.19.5 及更早
  版本会拒绝这样的快照及其归档。

### 回滚

恢复 v0.19.5 的镜像或二进制，沿用同一个缓存卷。v0.19.5 不认识这里引入的配置，
回滚前请先移除它们：遇到 `apt-proxy.yaml` 里列表形式的 `mode`，以及
`-mirror-election`、`-passthrough-follow-redirects` 这两个参数，它会启动失败；
文件里的 `mirrors.election` 和 `passthrough_follow_redirects` 会被忽略；逗号
分隔的 `--mode` 会被当作 `all`；含有 `official_url` 的 `distributions.yaml`
会被拒绝，此时它只使用内置发行版运行，并记录一条警告。

从 v0.19.4 或更早版本升级时，还请阅读 [v0.19.5 升级说明](v0.19.5.zh-CN.md)及其
链接的更早说明。

## 验证与产物

每项改动都通过 pull request 合入，CI 与安全扫描检查全部通过。合并后的代码树
通过了 18 个客户端镜像的真实客户端矩阵及其证据校验、`go test -race`，以及覆盖率
门禁（语句总覆盖率 96.8%）。发布工作流在发布产物之前会再次运行客户端矩阵。这些
带签名的本地测试仓库验证的是软件包安装与缓存复用，不代表对所有公共镜像或所有
客户端 CPU 架构的认证。详见 [verified client support](../client-support.md)。

产物与 v0.19.5 相同：Linux 和 macOS 的二进制归档，Linux 的 `.deb`、`.rpm`、
`.apk` 软件包，归档的 SBOM 和 `checksums.txt`。Docker Hub 和 GHCR 发布
`linux/amd64`、`linux/arm64` 和 `linux/arm/v7` 的镜像清单。

[完整对比：v0.19.5...v0.20.0](https://github.com/soulteary/apt-proxy/compare/v0.19.5...v0.20.0)
