## Changes since v0.19.3

- **Optional Proxmox repository examples.** [#174](https://github.com/soulteary/apt-proxy/pull/174)
  adds commented PVE, PBS Server, PBS Client and Ceph Squid entries to
  [`config/distributions.yaml`](../../config/distributions.yaml). They do not
  enable new routes or change the active default configuration.
- **A 95% aggregate statement-coverage floor.** [#175](https://github.com/soulteary/apt-proxy/pull/175)
  adds tests for configuration precedence, repository snapshots, Metalink,
  cache isolation, storage failures, resource admission and server lifecycle.
  The release report records 96.32% total statement coverage. The floor applies
  across `./...`, not to each package or to branch coverage. Command execution
  and the listener/reload loop were separated internally to test their behavior;
  the public command and signal interfaces are unchanged.
- **Dependency maintenance.** [#173](https://github.com/soulteary/apt-proxy/pull/173)
  updates health-kit to v4.0.4 and middleware-kit to v3.0.3. Go remains at 1.27.3.

## Upgrade

Replace the binary or pin the new container tag:

```sh
docker pull soulteary/apt-proxy:v0.19.4
# Equivalent registry:
docker pull ghcr.io/soulteary/apt-proxy:v0.19.4
```

No configuration migration is required when upgrading from v0.19.3. Existing
custom `distributions.yaml` files are not overwritten or automatically extended.
To use a Proxmox example, append the desired uncommented entry to your active
`distributions` list, keep each custom type unique, and reload distributions.
See the [PBS Client recipe](../../examples/proxmox/) and its repository scope.

For upgrades from v0.19.2 or earlier, v0.19.3 fixes URL joining when a mirror
root lacks its trailing slash. This prevents URLs such as
`/debian/pbs-clientdists/...`. v0.19.2 introduced host-and-path route priority
and strict distribution YAML validation; review its
[upgrade notes](v0.19.2.md), including `cache_control` spelling. Existing wrong
repository metadata cached before those fixes may require cache cleanup and
client index refresh; upgrading does not rewrite an already cached response.

## Validation and artifacts

The [release workflow](https://github.com/soulteary/apt-proxy/actions/runs/40728681270)
passed all 18 Linux AMD64 real-client targets, the evidence gate, Go tests with
race detection, and the 95% coverage gate before publication. These signed
local fixtures verify package installation and cache reuse; they do not certify
every public mirror or every client CPU architecture. See
[verified client support](../client-support.md).

The release provides Linux/macOS binary archives, Linux `.deb`/`.rpm`/`.apk`
packages, archive SBOMs and `checksums.txt`. Docker Hub and GHCR publish
`linux/amd64`, `linux/arm64` and `linux/arm/v7` manifests. ARMv6 has binary
archives and Linux packages, but no container image.
