# v0.19.2

APT Proxy v0.19.2 修复第三方软件源与内置发行版路径重叠时的仓库选择问题，
增加发行版 YAML 字段校验，并提供 Proxmox Backup Client 示例。

[English upgrade notes](v0.19.2.md)

## 本次改进

- **将 Proxmox 请求转发至配置的 Proxmox 仓库。** 同时匹配原始请求域名和路径的
  发行版配置，现在优先于通用路径规则。配置对应域名与路径后，
  `download.proxmox.com/debian/pbs-client/...` 请求不会再被内置 Debian
  `/debian/` 路由提前接走。这项修复由
  [#170](https://github.com/soulteary/apt-proxy/pull/170) 实现，对应
  [#167](https://github.com/soulteary/apt-proxy/issues/167)。
- **明确报告发行版字段错误。** 将 `cache_control` 拼成 `cache-control` 等未知字段，
  现在会返回包含字段名和行号的错误；同一文件中的额外 YAML 文档也会被拒绝。
- **完善示例与排查信息。** [Proxmox Backup Client 示例](../../examples/proxmox/)
  包含保留官方 HTTP 源地址的配置、独立本地路径别名，以及直连与代理请求的对照检查。
  URL 重写调试日志增加选中的发行版 ID。中英文文档说明了为何仅凭 `404` 或
  `cache: SKIP` 不能判断配置没有加载。
- **更新依赖与 CI 工具。**
  [#168](https://github.com/soulteary/apt-proxy/pull/168) 将 `health-kit/v4`
  从 v4.0.2 升至 v4.0.3；
  [#169](https://github.com/soulteary/apt-proxy/pull/169) 更新 Go 测试报告、
  Go Report Card、Docker 登录和 SARIF 上传工作流组件。Go 工具链沿用 v0.19.1
  已采用的 1.27.3。

## 升级注意事项

**发行版配置现在采用更严格的校验。** 升级前请检查 `distributions.yaml` 中的拼写
和非标准字段：

- 缓存指令字段使用 `cache_control`。
- 每个文件只保留一个 YAML 文档。
- 在已定义字段内使用锚点和合并。任意自定义的顶层锚点辅助字段需要调整到支持的结构中。

空文件仍然有效。这些规则只适用于发行版配置，不适用于主服务配置文件。

启动与重载的错误处理策略保持不变：启动时发行版文件无效，会记录警告并保留内置
发行版；重载失败时，继续使用当前已生效的路由配置。请通过启动或重载日志确认
自定义配置已成功加载。

`host_pattern` 仍用于路由优先级和后备匹配，不是域名访问控制规则。本地路径别名
继续可用。同等匹配条件下仍采用原有确定顺序。选中的发行版没有匹配的缓存规则时，
仍然返回 `404`，不会继续尝试另一个仓库。

## 发布前验证

修复前，已使用两个独立本地上游复现请求误入 Debian 的问题；修复后，新增的
33 个路由场景全部通过，并检查实际访问的上游、Host、路径和查询参数。发行版加载器
测试覆盖未知字段、空文件、额外 YAML 文档、支持的锚点与合并，以及重载失败后
保留现有配置。

本地完整测试集的 race 检查与 `go vet` 均通过，总语句覆盖率为 83.6%，超过项目
80% 的门槛。PR #170 的
[CI](https://github.com/soulteary/apt-proxy/actions/runs/40508913109) 和
[安全扫描](https://github.com/soulteary/apt-proxy/actions/runs/40508913111) 也已通过。
这些是本地与 PR 的验证结果；版本标签工作流会单独执行发布门禁。路由回归测试使用
受控本地上游，不代表已验证公网 Proxmox 仓库的实时可用性。
